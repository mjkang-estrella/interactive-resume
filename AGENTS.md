# Agent guide: interactive-resume

Read `README.md` first; it covers the architecture and the resume-update workflow.

## Ground rules

- `frontend/public/contents/resume.pdf` is the source of truth. The paper in `frontend/src/index.html` must match it word for word; do not "improve" resume wording on the paper without changing the PDF too.
- Detail pages in `frontend/src/pages/doc-pages/` may expand on a bullet, but never invent facts, metrics, or employers. Mark gaps with an HTML `<!-- TODO(MJ): … -->` comment instead.
- Keep the resume to one page: after editing the paper, check it still fits the 8.5×11 in paper in the browser.
- The site is static: no backend, API keys, or environment variables. Keep it that way unless asked.
- `/llms.txt` is generated by `frontend/plugins/llms-txt.ts`. After content changes, open `/llms.txt` in the dev server and check the new text reads well.

## Checks

```bash
npm run lint    # type-checks the app, vite.config.ts, and plugins/
npm run build   # must succeed before deploying
```

For UI changes, run `npm run dev` and click through the bullets you touched, on a wide screen and a phone-sized one.
