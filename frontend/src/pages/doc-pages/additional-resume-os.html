Resume OS

This is my interactive resume. Start with the one-page summary, then open any clickable bullet to read the decisions and work behind it.

How to use this page

  1. Click a resume bullet. Its story opens in the detail sheet, and the selected bullet is highlighted.
  2. Scroll inside the detail sheet to read the full story and see supporting images. Click an image to open it at full size.
  3. Choose another bullet to switch stories, or use the close button to return to the resume. On a phone, stories appear below the resume.

Hover over a company name for a short introduction. For the conventional one-page version, use the PDF icon at the top of the resume.

Ask a follow-up question

Use Ask an AI in the bottom-right corner to choose ChatGPT, Claude, or Google AI Mode. It opens your chosen assistant with a question and a link to the resume and stories. You can also copy the prompt.

Try asking about a product decision, my role in a project, or how my experience relates to a job. The assistant can read the same material at llms.txt.

Why I built it

A resume makes it easy to scan roles and results, but a short bullet leaves out most of the work. I wanted a place to explain what we tried, which constraints mattered, and why we changed direction.

Resume OS keeps that detail attached to the relevant bullet. Readers can choose which projects to explore without working through a separate portfolio.

From the first prototype to this version

I built the first version with Codex and Zed, wrote the project stories in Notion, and used GitHub and Vercel to manage and publish the site. That version included an embedded interview bot built with ChatKit and Agent Builder, plus a waitlist backed by Supabase.

The current site is static. It publishes the resume and stories for external assistants to read, without running a chat backend or collecting waitlist signups. The clickable bullets, highlighting, and animated sheets remain the main way to explore.

What I learned building it

I built the first version in about a week. Coding agents helped me get it working, but I still had to decide how someone would discover the interaction. The moving cursor demonstrates a click, and the highlight connects the resume bullet to the story that opens beside it.

Small layout and timing choices needed repeated checks in the browser. Being able to inspect the code and adjust it myself made that work easier.
